# 阿里云服务器部署指南

把掌中灵中继服务跑在阿里云 ECS 上。全程约 15 分钟，其中大半在等镜像下载。

---

## 零、前置条件

| 项 | 要求 |
|---|---|
| 实例规格 | 最低 **1 核 2 G**（服务常驻内存约 100–150 MB）；推荐 2 核 2 G |
| 系统 | Ubuntu 20.04+ / Alibaba Cloud Linux 3 / CentOS 7+ 均可 |
| 公网 IP | `203.0.113.10`（**示例**；本文档统一用它作占位，请替换为你自己实例的公网 IP） |
| 磁盘 | ≥ 20 GB（数据库与截图文件很小，长期运行也就几百 MB） |
| 网络 | 实例需能访问公网（拉取镜像与 npm 包） |

登录服务器：

```bash
ssh root@203.0.113.10
```

## 一、安装 Docker

阿里云服务器从官方源装 Docker 可能很慢，用带阿里云镜像的安装方式：

```bash
curl -fsSL https://get.docker.com | sh -s -- --mirror Aliyun
```

装完后设置开机自启并启动：

```bash
systemctl enable --now docker
docker --version
docker compose version
```

两条命令都能输出版本号即成功。

> **如果 `docker compose` 报找不到命令**：说明 Docker 版本偏老，补装插件
> `apt install -y docker-compose-plugin`（Ubuntu）或 `yum install -y docker-compose-plugin`（CentOS）。

## 二、配置 Docker 镜像加速 ⚠️ 别跳过

国内直接拉 `node:22-bookworm-slim` 会很慢甚至超时。**这是最常见的失败原因。**

阿里云给每台 ECS 提供免费专属加速地址：

1. 登录阿里云控制台 → 搜索「**容器镜像服务**」→ 左侧「**镜像工具 → 镜像加速器**」
2. 复制页面上的专属地址（形如 `https://xxxxxx.mirror.aliyuncs.com`）
3. 在服务器上执行：

```bash
sudo mkdir -p /etc/docker
sudo tee /etc/docker/daemon.json <<'JSON'
{
  "registry-mirrors": ["https://把这里换成你的专属地址.mirror.aliyuncs.com"]
}
JSON
sudo systemctl daemon-reload
sudo systemctl restart docker
```

验证生效：

```bash
docker info | grep -A2 "Registry Mirrors"
```

> 若该文件已存在且内有其他内容，请手动在 JSON 中追加 `registry-mirrors` 字段，不要直接覆盖。

## 三、上传项目文件

你只需要传 **`server/` 和 `deploy/` 两个目录**。

### 方式 A：上传打包好的压缩包（推荐，最省事）

本地已生成 `zzl-deploy.tar.gz`（已排除 `node_modules`、数据库等无用内容，仅几十 KB）。

在 **本地 Windows 的 PowerShell 或 Git Bash** 中执行：

```bash
# 上传
scp D:\pwg\监管软件\zzl-deploy.tar.gz root@203.0.113.10:/opt/

# 解压（在服务器上执行）
ssh root@203.0.113.10
mkdir -p /opt/zzl && cd /opt/zzl
tar -xzf /opt/zzl-deploy.tar.gz
ls        # 应看到 server 和 deploy 两个目录
```

### 方式 B：用 WinSCP / FinalShell 图形化上传

新建 SFTP 连接（协议 SFTP，主机 `203.0.113.10`，端口 22，用户名 `root`，密码为你的实例密码），
把 `server` 和 `deploy` 两个文件夹拖到 `/opt/zzl/` 下。

> ⚠️ **不要上传 `server/node_modules`** —— 那是本地 Windows 的依赖，Linux 上无用且体积大。
> 镜像构建时会自动重新安装。

### 方式 C：直接 scp 两个目录

```bash
ssh root@203.0.113.10 "mkdir -p /opt/zzl"
scp -r D:\pwg\监管软件\server root@203.0.113.10:/opt/zzl/
scp -r D:\pwg\监管软件\deploy root@203.0.113.10:/opt/zzl/
ssh root@203.0.113.10 "rm -rf /opt/zzl/server/node_modules /opt/zzl/server/data"
```

最终目录结构必须是：

```
/opt/zzl/
├── server/
│   ├── Dockerfile
│   ├── package.json
│   ├── package-lock.json
│   ├── src/
│   └── scripts/
└── deploy/
    ├── docker-compose.yml
    ├── .env.example
    └── install.sh
```

## 四、配置 .env

```bash
cd /opt/zzl/deploy
cp .env.example .env

# 生成一个强随机密钥并写进去
SECRET=$(head -c 32 /dev/urandom | od -An -tx1 | tr -d ' \n')
sed -i "s|^JWT_SECRET=.*|JWT_SECRET=${SECRET}|" .env

cat .env | grep -E '^(JWT_SECRET|TZ)='     # 确认已写入
```

> 用 `./install.sh` 部署的话，这一步**会自动完成**（脚本会生成随机密钥写入 `.env`），无需手动执行。

### ⚠️ 两个必须正确的变量

服务启动前会做前置检查，任一项不过就**拒绝启动**（这是有意为之，不是故障）。

**1. `JWT_SECRET` —— 留空等于没有鉴权**

| 情况 | 结果 |
|---|---|
| 为空（`JWT_SECRET=`） | **拒绝启动** |
| 生产环境短于 32 字符 | **拒绝启动** |
| 生产环境用内置默认值 | **拒绝启动** |

> 为什么专门拦「留空」：`config.js` 里写的是 `process.env.JWT_SECRET ?? '默认值'`，
> 而 `??` **只对 null / undefined 生效** —— 留空拿到的是**空字符串**，不等于默认值，
> 于是原有的"是否使用默认密钥"检查也不成立，服务会带着**空密钥**正常启动。
> 那时任何人都能用空串签出一个合法的家长令牌，直接接管全部设备。
> 这既不是"弱鉴权"而是"没有鉴权"。

**2. `TZ` —— 必须与设备端一致（默认 `Asia/Shanghai`）**

额度日的"归日点"由**进程本地时区**决定：服务端用 `getFullYear/getHours`，
被控端用设备本地时区。容器默认是 **UTC**，与被控端（北京时间）差 8 小时。

后果不是"差一点"而是**整天错位**：

```
平板（北京时间）把 9/19 早 8 点的使用记录标成 dayKey = 2026-09-19
服务器（UTC）此刻的 todayKey() 还停留在  2026-09-18
→ 家长打开「使用报告」看到「今日用量 0 分钟」
→ 加时授权也会落在错误的日子上
```

更隐蔽的是：glibc 读 `TZ` 依赖 `/usr/share/zoneinfo`，
**镜像里缺 tzdata 时 `TZ` 会被静默忽略** —— 看起来设了、实际仍按 UTC 跑，没有任何报错。
因此服务启动时会把"按 ICU 算出的应有偏移"与"进程实际生效的偏移"对比一下，
不一致就拒绝启动并直接告诉你原因。Dockerfile 已按需安装 tzdata，正常不会触发。

### 其余配置

通常不用改。对外端口默认已是 **8111**（避开服务器上常被占用的 8080），
想换别的端口改 `.env` 里的 `APP_PORT` 即可（**App 端「服务器设置」要同步改**）；
容器内部仍固定监听 8080，无需关心。

完整的可用变量清单见 `.env.example`，每一项都与 `server/src/config.js` 逐项对应，
可用 `npm run env:check` 自动校验（改名或新增变量忘了同步会直接报错）。

> `.env.example` 里每一项都有注释说明。注意 **docker compose 的 `env_file` 不支持行内注释** ——
> 注释必须独占一行，否则会连同 `#` 后面的内容一起被当成变量值。

## 五、启动服务

### 一键脚本（推荐）

```bash
cd /opt/zzl/deploy
chmod +x install.sh
./install.sh
```

脚本会自动检查 Docker 环境、生成密钥、构建镜像、启动容器并做健康检查。

### 手动执行

```bash
cd /opt/zzl/deploy
docker compose up -d --build
```

首次构建需要下载 Node 镜像和 npm 依赖，约 **1–3 分钟**。
看到 `Started` 即成功。

查看状态与日志：

```bash
docker compose ps
docker compose logs -f zzl-server
```

日志中出现下面这几行说明启动成功：

```
掌中灵中继服务已启动 — http://0.0.0.0:8080
WebSocket 端点 — ws://0.0.0.0:8080/ws
数据库文件 — /data/app.db
```

## 六、放行安全组 ⚠️ 最容易漏的一步

**服务起来了但 App 连不上，99% 是这一步没做。**

1. 阿里云控制台 → **云服务器 ECS** → 实例列表 → 找到你的实例
2. 左侧「**安全组**」→ 点击安全组 ID 进入 →「**访问规则**」→「**入方向**」→「**手动添加**」

| 字段 | 值 |
|---|---|
| 授权策略 | 允许 |
| 优先级 | 1 |
| 协议类型 | **自定义 TCP** |
| 端口范围 | **8111/8111** |
| 授权对象 | `0.0.0.0/0` |
| 描述 | 掌中灵中继服务 |

保存后立即生效，无需重启实例。

> 若你把 `.env` 里的 `APP_PORT` 改成了别的端口，这里要填对应的端口号。

同时确认实例自带的系统防火墙没有拦截：

```bash
# Ubuntu
ufw status
# CentOS / Alibaba Cloud Linux（一般默认关闭，无需处理）
systemctl status firewalld
```

## 七、验证

**服务器本机自测：**

```bash
curl http://127.0.0.1:8111/api/health
# 期望输出：{"ok":true,"service":"zhangzhongling","serverTime":1789...}
```

**跑一遍端到端自检**（会自动走完注册→配对→心跳→WebSocket→策略→指令→授权全流程）：

```bash
# 推荐：一条命令跑完全部九套（合计 391 项）
docker compose exec zzl-server node scripts/alltests.mjs

# 或者只跑不需要服务的模块级自检
docker compose exec zzl-server node scripts/alltests.mjs --no-smoke
```

单独跑某一套：

```bash
docker compose exec zzl-server node scripts/smoke.js
# 期望：结果：54 项通过，0 项失败

docker compose exec zzl-server node scripts/smoke-m4.js
# 期望：结果：78 项通过，0 项失败

docker compose exec zzl-server node scripts/smoke-m5.js
# 期望：结果：68 项通过，0 项失败

docker compose exec zzl-server node scripts/smoke-m6.js
# 期望：结果：65 项通过，0 项失败
```

| 套件 | 项数 | 需要服务 | 覆盖 |
|---|---|---|---|
| `envcheck.mjs` | 8 | 否 | 环境变量契约（代码读取 vs 文档声明） |
| `preflighttest.mjs` | 28 | 否 | 启动前置检查（密钥强度、时区正确性） |
| `dbtest.mjs` | 26 | 否 | 数据库 schema 与密码学 |
| `migrationtest.mjs` | 28 | 否 | 老库升级不坏（独立库，可与服务并存） |

| `smoke-m5.js` | 68 | **是** | M5 端到端 |

> ⚠️ **不要在机器负载很高时跑端到端自检**（例如同时在编译 APK）。
> 与服务的往返超时会表现为零星的失败项，而那些失败**与被测代码无关**，很容易误导排查方向。
> 真遇到零星失败，先空载重跑一次再下结论。

| 字段 | 值 |

| 主机 | `203.0.113.10` |

## 八、日常运维

```bash
cd /opt/zzl/deploy

docker compose ps                    # 查看运行状态
```

### 数据备份

数据库与截图文件都在 Docker 卷 `zzl-data` 里，映射到容器内 `/data`。

```bash
# 备份到服务器本地
docker run --rm -v zzl-data:/data -v /opt/backup:/backup alpine \
  tar -czf /backup/zzl-$(date +%F).tar.gz -C /data .

# 拉回本地
scp root@203.0.113.10:/opt/backup/zzl-*.tar.gz D:\backup\
```

建议加一条 crontab 每天自动备份：

```bash
crontab -e
# 追加：
0 3 * * * docker run --rm -v zzl-data:/data -v /opt/backup:/backup alpine tar -czf /backup/zzl-$(date +\%F).tar.gz -C /data . && find /opt/backup -name 'zzl-*.tar.gz' -mtime +14 -delete
```

### 更新到新版本

```bash
cd /opt/zzl/deploy
./install.sh --update
```

## 九、排错手册

| 现象 | 原因与处理 |
|---|---|
| `docker compose up` 卡在 `Pulling node` 很久 | 没配镜像加速。执行本文**第二步** |
| `docker compose up` 报 `manifest unknown` / 超时 | 同上；或临时改用 `--build-arg NPM_REGISTRY=https://registry.npmjs.org` |
| 构建报 `npm ci` 失败 | `package-lock.json` 没上传。补传后重新构建 |
| 构建报 `node:sqlite 可用` 这步失败 | 拉到的 Node 镜像低于 22.13。执行 `docker compose build --no-cache` 重新拉取 |
| 容器启动后立刻退出 | `docker compose logs zzl-server` 看报错。多半是 `JWT_SECRET` 为空 |
| 本机 curl 通、公网不通 | 安全组未放行（第六步）；或实例绑定的安全组不是你在改的那个 |
| App 提示「连接超时」 | 安全组 / 端口填错 / 服务器服务未启动，三者逐个排除 |
| App 提示「拒绝连接」 | 端口填错，或服务没在监听该端口 |
| 日志报 `SQLITE_CANTOPEN` | `/data` 卷挂载异常，`docker compose down && docker compose up -d` |
| 磁盘告警 | 清理旧备份；数据库本身很小，通常不是它的问题 |

查看容器内实际情况：

```bash
docker compose exec zzl-server sh
ls -lh /data          # 数据库与截图
node -v               # 确认 Node 版本 ≥ 22.13
```

## 十、后续接入域名与 HTTPS

目前是 IP 直连、走 HTTP。日后想换成 `https://你的域名`：

1. 域名解析 A 记录指向 `203.0.113.10`
2. 安全组放行 **80** 和 **443**
3. 新建 `deploy/Caddyfile`：

```
你的域名 {
    reverse_proxy zzl-server:8080
}
```

4. 编辑 `docker-compose.yml`：删掉 `zzl-server` 的 `ports` 段（不再对外暴露 8080），
   并放开文件末尾注释掉的 `caddy` 服务
5. `docker compose up -d --build` —— Caddy 会自动申请并续期 Let's Encrypt 证书
6. App 端「服务器设置」把协议改为 `https`、主机改为域名、端口填 `443`

**业务代码与 App 代码都无需改动**，这正是当初做成可配置的目的。

## 十一、被控端设备准备（家长手机上装完后）

服务跑起来只完成了"中继就绪"。被控端那台平板还需要两项准备，
**建议在给孩子的平板之前一次做完**。

### 11.1 权限与保活（必做）

在被控端 App 里逐项点「去开启」：

| 项 | 为什么必须 |
|---|---|
| 无障碍服务 | 感知前台应用、执行"回到桌面" |
| 使用情况访问 | 统计各应用时长 |

> ⚠️ **Android 13+ 的坑**：从非官方商店侧载的 App，默认**禁止**开启无障碍与使用情况访问。
> 点开关时会提示"出于安全考虑，此设置当前不可用"。正确路径：
> 设置 → 应用 → 掌中灵（被控端）→ 右上角 ⋮ → **允许受限设置** → 再开无障碍。

再逐项处理保活：

| 项 | 位置 |
|---|---|
| 电池优化豁免 | 权限页「电池优化」按钮直接跳转 |
| 自启动 / 后台运行白名单 | 厂商 ROM 差异大，权限页会按机型给出路径 |
| 通知权限 | Android 13+ 需要，否则常驻通知不显示剩余额度 |

被控端「防卸载加固」卡片会显示**保活健康度**（前台服务 / 电池优化 / 精确闹钟 / 厂商白名单），
四项全绿才算稳。

### 11.2 Device Owner 激活（可选，但强烈建议）

这是**唯一能真正阻止卸载**的模式。不做也能用（走设备管理器模式），
但孩子可以在「设置 → 安全 → 设备管理应用」里取消激活后卸载。

**准备条件（三条都满足才能激活）：**

1. 平板上**没有添加任何账号**（Google / 厂商账号都要先移除）
2. 平板上**没有其他 Device Owner**（之前激活过就只能恢复出厂）
3. 平板已开启「开发者选项 → USB 调试」

**执行**（在电脑上，需要 adb）：

```bash
# 1. 打包里的脚本拷到电脑，装好 Android SDK Platform Tools
adb devices                            # 确认设备已授权

# 2. 在被控端 App 里先设置好三级离线密码（重要！）

# 3. 一键激活
bash activate-device-owner.sh
```

脚本会自动：探测设备上装的是 debug 还是 release 包 → 检查现有 Device Owner →
检查账号 → 执行 `dpm set-device-owner` → 验证结果，并在失败时打印具体原因。

**激活后的两个代价，务必知悉：**

- **无法通过 App 自行取消**。退出管控只能靠离线超级密码，或恢复出厂设置。
- **请务必牢记离线超级密码。** 忘记密码且完全离线时，只能恢复出厂。

> 「恢复出厂设置」**默认不被禁用** —— 这是刻意留的后路，
> 防止家长忘记密码后设备彻底变砖。

### 11.3 验收清单

装完两个 App 后按序验证：

1. 控制端注册 → 生成 6 位配对码
2. 被控端输入配对码 → 显示"绑定成功"，控制端设备列表出现该设备（在线）
3. 控制端「时长规则」把上学日总时长改成 **1 分钟** → 保存
4. 被控端随便打开一个应用 → **1 分钟后应弹出全屏拦截页并回到桌面**
5. 拦截页点「申请加时」→ 控制端顶栏出现角标 → 审批（可打折批准）→ 被控端立即解锁
6. 控制端「设备加固」→ 设置三级离线密码 → 被控端拦截页下方的「家长密码」框输入 → 验证通过后出现操作按钮
7. 控制端「限制工具」→ 立即锁定 → 被控端所有应用被拦
